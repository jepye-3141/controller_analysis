# ATLIS Sims

Quadrotor UAV swarm control comparison framework. Compares LQR, continuous SMC, discrete SMC, and PID controllers across step, figure-8, spiral, and ballistic stabilization trajectories using Simulink models. Includes a 6-DOF 120mm mortar ballistic simulation (McCoy Ch. 9) used to generate realistic deployment initial conditions.

## Running simulations

No build/lint step -- everything runs inside MATLAB.

- `Ballistics_Simulation-master/` must be on the MATLAB path. `analysis.m` and `trajectory_optimization.m` call `eom2()` and `aero_constants()` without `addpath`, so launch MATLAB from the project root with that folder added, or run `addpath("Ballistics_Simulation-master")` first.
- `constants.m` must run before any simulation -- it defines physical parameters and computes the discrete LQR gains (`Kp_d`, `Ki_d`) used by the Simulink models. `analysis.m` calls it automatically at the top.
- Full regeneration: run `analysis.m` from the project root. Produces every Simulink sim result and writes `figs/1..39_*.{png,eps}`. Long-running; a prior workspace is cached in `logs/analysis_log.mat` (~82 MB) and can be `load`ed to skip re-simulating.
- Saturation comparison sweep: run `trajectory_optimization.m` → calls `sweep_landing_centroid(traj_params, true)` **twice** (saturation on and off), then `plot_saturation_comparison`. Each sweep runs the dSMC deploy×cross-track×neighbor grid (~140 valid trials), builds the centroid + radial-reachability summary, and writes suffixed `figs/TO_01..TO_07_sat_{on,off}` + `logs/trajectory_optimization_log_sat_{on,off}.mat`; the comparison writes `figs/SAT_CMP_summary`. Wall ≈ 10–16 min per sweep on 12 workers when the rapid-accelerator target rebuilds (model edited); ≈ 6 min per sweep warm (measured 2026-07-03).
- Targeting LHS lookup: **current driver is `j3_lut_regen.m`** (executed 2026-07-10 — see Targeting optimization), which regenerated canonical `logs/centroid_lookup_log.mat` (N=41: 40 LHS + injected reference row; `p ∈ [−12,12]`; per-sample `radial_profile`; checkpointed/resumable). Measured wall: **2.3 h total; warm `visualize=false` sweeps ≈ 1.3 min/sample** (the ~6 min/sweep figure elsewhere includes TO figures + a 200–400 MB workspace save; the first ~6 samples pay rapid-accel warm-up at 14–20 min). The older `centroid_lookup_table.m` still carries the pre-J3 config (`p ∈ [−2,2]`, N=20, no `radial_profile`) — don't run it without updating those.
- Surrogate optimization: run `surrogate_optimize.m`. Fits four GP surrogates (`fitrgp`, ARD Matérn-5/2) on `logs/centroid_lookup_log.mat`, runs multi-start `fmincon` on the scalarised objective `J = ‖p_centroid − p_target‖² − λ·half_radius`, writes `logs/surrogate_optimize_log.mat` and `figs/SO_01_predicted_J_slices.png`. With `verify=true` runs one ground-truth `sweep_landing_centroid` at the predicted optimum (~16 min). **For the J3 pass use `j3_surrogate_refit.m` instead** (zero-success masking, corrected NaN-hr handling, `area_proxy` mode, LOO-RMSE, λ-sweep; writes non-canonical `logs/surrogate_refit_j3_<hr_mode>.mat`). **The area_proxy refit was promoted to the canonical SO log on 2026-07-10** (author decision) — do not re-run `surrogate_optimize.m` as-is, it would overwrite the promotion with a clamp-mode fit.
- Re-render figures without re-simulating: `replot_TO_04.m` / `replot_TO_07.m` (from `logs/trajectory_optimization_log.mat`), `replot_LUT_01.m` (LUT_01), `replot_SO_01.m` (SO_01). Useful when iterating on visualization only.
- Ballistic sim alone: `Ballistics_Simulation-master/Mortar_Sim.m` runs the 6-DOF mortar sim standalone and writes `logs/ballistic_log.mat`.

Required toolboxes: Simulink, Control System Toolbox (`lqrd`, `ctrb`, `obsv`, `ss`), Navigation Toolbox (`eul2rotm`; `minsnappolytraj` for path planning), Optimization Toolbox (`fmincon`), Statistics and Machine Learning Toolbox (`lhsdesign`, `fitrgp`), Symbolic Math Toolbox (used only in `deprecated/lqr_linearization_and_path_planning.m`), and Aerospace Toolbox (`gravitywgs84` in `Ballistics_Simulation-master/aero_constants.m` — omission found by the 2026-07-10 bugsweep).

Called by the entry points above (or run manually); not simulation drivers themselves:

Emits **both** `name_base.png` (ContentType `image`) and `name_base.eps` (ContentType `vector` by default; pass `EPSContentType="image"` for surf/heatmap figures like TO_07) at `Width=2000, Height=1400, Resolution=300, Padding=40`. Nearly every plotting script calls this — use it instead of raw `exportgraphics()`.
- `set_default_fonts.m` -- Applies AIAA-style `groot` defaults (Times; 16 pt axes/text, 18 pt title, 14 pt legend/colorbar; 1.25 pt lines; grid alpha 0.25). Call at the top of any figure-producing script.
- `ryg_cmap.m` -- Red→yellow→green reachability colormap `ryg_cmap(n_half)` (0=red, 0.5=yellow, 1=green; default 64×3). Shared by all TO/LUT/SO reachability figures (the TO_04 note under Conventions refers to this file).
- `plot_saturation_comparison.m` -- `plot_saturation_comparison(out_on, out_off)` builds the saturation ON-vs-OFF summary (2×2: radial profile, centroids, stats) → `figs/SAT_CMP_summary.{png,eps}`. Takes the two `sweep_landing_centroid` output structs **directly** (not the `.mat` logs). Called by `trajectory_optimization.m`.
- `ballistic_success.m` -- Post-processing STABILIZE success criterion `[success, info] = ballistic_success(t, pos, vel, target_xy, v0_norm, expected_T, opts)`: full duration (blowup guard never tripped) + final XY ≤ `ReachTol` (10 m) + velocity ratio ≤ `VelRatioMax` (2) over the whole trace + rotation-rate ratio ≤ `RotRatioMax` (2, vs `RotRefNorm = ‖[π π π]‖`) evaluated only for `t > RotGraceT` (default **1 s** — the paper's grace window excluding the ballistic-separation arrest transient; `info` reports both whole-trace `max_rot_ratio` and criterion `max_rot_post_ratio`). The rotation clause is **live since 2026-07-03**: all four `*_single` models log `rotvelout` (a branch of the same plant port-4 signal the termination charts norm) and both scoring paths pass `RotVel=`. That signal is the **Euler-angle rate vector `[θ̇ φ̇ ψ̇]`** (`system_dynamics.m:44-46`), not body rates ω — same measure the historical ratio charts enforced. Gotcha: `rotvelout.Data` is `[3×1×T]` in lqr/dsmc but `[T×3]` in pid/smc; extract with `r = squeeze(...); if size(r,2) ~= 3, r = r.'; end`, not the fixed `posout`-style one-liner. All bounds name-value configurable; `info` carries per-condition flags and measured extrema. Used by `analysis.m` (envelope, all five arms) and `sweep_landing_centroid.m` (`stable` flag + per-trial `results(...).criteria`). The in-model 1e5 termination charts (all four single models, uniform since 2026-07-03) are only numerical-blowup guards, not the criterion (see Ballistic simulation §2 for the normalization history).
- `ballistic_deploy_state.m` -- **The deploy-seed builder (added 2026-07-10, the deploy-attitude fix).** `[xi, att] = ballistic_deploy_state(v, h, r, pos)` maps ballistic trajectory slices (NWU) to the drone 12-state seed `xi = [vel_body; rotvel_body; theta; phi; psi; pos]`. Attitude derives from the **pointing vector** (cols 7:9, renormalized after interpolation): body x-axis along r, zero roll about it (packaging convention) — `psi = atan2(r2,r1)`, `theta = asin(r3)`, `phi = 0`; velocities/rates map world→body via `M.'` where `M` (body→world, orthogonal, det −1) is hand-built to match `system_dynamics.m`'s ZYX rows exactly (world z-up, body z-down; `M(:,1) = r_hat` exactly). Callers: `sweep_landing_centroid.m` (per-station) and `analysis.m` (apogee test + envelope loop). **Bugsweep 2026-07-10 (FIXED): the `rotvel0 = M.'*h` seed was sign-mirrored** (pseudovector through the det = −1 map — realized world spin −h); now `rotvel0 = −(M.'*h)`, verified to realize +h to 1.6e-16 (see the bugsweep status note under Ballistic simulation). Trajectory cols 13:15 are not consumed anywhere; since the plan-2 remediation they carry the **same derived attitude backfilled by eom2** (valid, radians — equal to this helper's `xi(7:9)` at exact rows), but interpolated stations must still interpolate r (cols 7:9) and call this helper, never interpolate the angle columns.
- `set_omega2_max.m` -- `set_omega2_max(val)` rewrites the `Omega2_max = …;` literal **inside `dsmc_constraints.m` on disk** (regexprep + fwrite), not a runtime/global param. Manual helper for the Omega² saturation sweep; it leaves the source file mutated (git-dirty) at whatever value it last set.
- `init.m` -- One-liner that rebuilds the bus object via `Simulink.Bus.createObject(constants_struct)` (`wc -l` reports 0 only because there is no trailing newline — it is **not** empty). Run after `constants.m` when a model needs the bus regenerated.
- `system_dynamics.m` -- Standalone nonlinear 12-state quadrotor ODE `xdot = system_dynamics(A, B, u, x, constants)` (A,B unused; `u`=[T Mx My Mz] with `T` absolute, not delta). **Confirmed caller (2026-07-03): it IS the simulated plant** — `actual_discrete_smc_controller.slx` wraps it in a one-line MATLAB-Function chart, and `discrete_smc_swarm_single.slx` pulls that model in as the referenced "Leader" subsystem. (Found by unzipping the `.slx` archives and grepping `simulink/stateflow/chart_*.xml` — see `MEMORY.md`.) Applies `u` with no saturation/clipping of any kind; the model's only dynamic guard is a termination chart ("MATLAB Function2" in `discrete_smc_swarm_single.slx`) that stops STABILIZE sims when `norm(vel)` or `norm(rotvel)` ≥ 1e5 — a **numerical-blowup guard only**, deliberately NOT the success criterion (that is applied post-hoc by `ballistic_success.m`). See `docs/paper_code_agreement_saturation.md` for the full paper-vs-code audit built on this.

## Control functions as MATLAB files

The codebase is migrating control logic out of Simulink MATLAB-Function blocks into standalone `.m` files that the Simulink models call. Standalone files are easier to read, diff, and review than embedded block code. The two files in this campaign are:

- `dsmc_no_constraints.m` -- The user's original discrete SMC, lifted verbatim from the Simulink block. Mathematical structure is frozen; treat it as the canonical baseline. It is deliberately **unclipped** (the only truly-unconstrained code path) and is invoked at runtime via the `constants.unconstrained` dispatch at the top of `dsmc_constraints.m` (the `analysis.m` envelope "nosat" arm).
- `dsmc_constraints.m` -- Plan A+ augmented dSMC. This is the file under active development.

Both have the signature `u = fn(A, B, state, xd, x0, constants)`. `A` and `B` are kept for Simulink interface compatibility but unused. `constants` is the bus signal built by `constants.m` (fields: `g, l, Jmp, Jxx, Jyy, Jzz, kmt, kwt, dt, K, m, m_uncertain, saturation_on, unconstrained`). Both files read `g, l, Jmp, Jxx, Jyy, Jzz, dt` and `m_uncertain` (used as the plant mass, so mass-uncertainty injection flows through it); `dsmc_constraints.m` additionally reads `saturation_on` and `unconstrained` (when the latter is true it delegates to `dsmc_no_constraints.m` before touching its own persistents and returns that raw command). Both use `persistent` variables to retain controller state across ticks, and both clip the `s_z`/`s_psi` sliding variables to `[-2, 2]` — this clip is canonical and load-bearing (removing it lands zero successful sweep trajectories; see `MEMORY.md`).

### dsmc_constraints.m structure

Plan A+ augments the canonical control law with:

1. **Auxiliary state `xi` (4-vector)**: one channel per actuator (thrust, Mx, My, Mz). Modified sliding variable `tilde_s = s - D*xi` substitutes for `s` in eqs 21, 22, 38, 39. The deficit-coupling matrix `D` has same-channel entries (`D11`, `D22`, `D33`, `D44`) and cross-channel entries (`D21`, `D31`) that capture how thrust deficit perturbs roll/pitch sliding. See Plan A+ §4.1, §4.2.
2. **Priority-weighted allocation in Omega^2-space**: closed-form sequential scaling with operational priority `Mx, My > T > Mz`. Implemented as `priority_weighted_allocate()` (local function in same file). Yaw scales toward zero first, then thrust, then a joint roll/pitch fallback. Saturation bounds: `Omega2_min = 0.0`, `Omega2_max = 2` — a hard-coded literal that `set_omega2_max.m` rewrites in place on disk during the saturation sweep (currently set just past the empirical breakpoint — see `MEMORY.md` saturation-sweep entry).
3. **Matched contraction**: `k_xi = [nuz; nu3; nu4; nupsi] * dt` (Plan A+ §4.4). Per-channel rate matched to the corresponding reaching-law gain.
4. **POST-saturation feedback**: `ukm1` stores the saturated command, so the gyroscopic-precession `Omegar` reflects actual rotor speeds and the deficit `delta_u = u_unc - u_bar` drives the auxiliary update.
5. **Master toggle `saturation_on`**: read from the bus (`constants.saturation_on`). When `false`, the controller bypasses allocation and anti-windup (`delta_u = 0`, `xi` stays 0, `tilde_s` collapses to `s`), so the control laws match `dsmc_no_constraints.m` — but see item 6: the returned command is still clipped. Sweeps set it per-trial (`analysis.m` envelope loop, `trajectory_optimization.m` on/off runs, `sweep_landing_centroid` from `traj_params`).
6. **Hard per-rotor clip (STEP 12b, both branches; added 2026-07-03)**: after the allocation/bypass branch, `u_bar` is mixed to Omega²-space, clamped to `[Omega2_min, Omega2_max]`, and remixed — same `TM` and bounds as the allocation. Under `saturation_on=true` this is a **no-op** (every allocation return path already lies in the box; a material behavior change there indicates an allocation bug — useful regression property). Under `false` it makes the OFF branch the **naive per-rotor-clipped baseline** of the paper. `dsmc_no_constraints.m` remains unclipped — the only truly-unconstrained code path. **Re-run outcome (2026-07-03)**: everything regenerated. ## Architecture

- Quadrotor: 12-state linearized model. State `[vx vy vz wx wy wz theta phi psi x y z]`; control `[T Mx My Mz]` with `T` as delta from hover weight (`m*g`).
- LQR uses augmented 15-state model with 3 integral states on position; discrete at 50 Hz (`lqrd(..., 1/50)`).
- dSMC controllers run at 50 Hz (`constants.dt = 1/50`, carried on the `constants` bus and read by the MATLAB-Function block). LQR's 50 Hz is set independently via `lqrd(..., 1/50)` in `constants.m`; the two rates happen to match but live in different places, so changing one does not change the other. (Historically dSMC ran at 200 Hz — a `dt=1/200` comment still survives in `dsmc_constraints.m` — but the working value is now `1/50`; confirmed intentional.)
- Swarm: 10 drones (1 leader + 9 followers) initialized with X-axis offsets `[0, 1, 2, 3, 4, 5, -1, -2, -4, -3]` m — the model's `posout` drone order (leader index 1). Mirrored by the plotting `offsets` matrix (`analysis.m:586`, 3×N, only col 1 used) and the `initial_positions` reference feeding the delta-distance heatmaps (`analysis.m:1472`). **Fixed 2026-07-07:** `initial_positions` previously used a permuted order `[0,1,-1,2,3,4,-2,-3,5,-4]` (right set, wrong order) that mismatched `posout` and injected up to 8 m of spurious deviation into figs 19–34; `offsets` carried a dead `+3` typo. Both realigned to `posout` order (t=0 artifact now 0.000 m) — **regenerate `analysis.m` to refresh figs 19–34 on disk**.
- Trajectory cases are integer-coded: `STEP=1`, `F8=2`, `SPIRAL=3`, `STABILIZE=4`. Set via the `simcase` workspace variable.

## parsim wiring in sweep_landing_centroid.m

The dSMC sweep runs trials in parallel via `parsim` with `'TransferBaseWorkspaceVariables', 'off'`. Every base-workspace variable the model needs is explicitly `setVariable`'d. The **7 static variables** (`A`, `B`, `constants_struct`, `constants_struct_bus`, `dt`, `x0_step`, `xf`) are applied **once** to a template `Simulink.SimulationInput` (`simIn_template`) which is then copied per trial; the **3 per-trial variables** (`xi`, `xf_ballistic`, `simcase`) are set on each copy. (There is no variable literally named `static_vars` — the static list lives inline near the top of the build loop.) `sweep_landing_centroid` calls `constants` internally so these all exist before parsim configures workers. If you edit `discrete_smc_swarm_single.slx` to reference a new base-workspace variable, add it to the static `setVariable` block — otherwise the sweep will silently fail or error per-trial. Model **outputs** need no such wiring: a new ToWorkspace block (e.g. `rotvelout`, added 2026-07-03) simply appears on each trial's `SimulationOutput`. Use `Simulink.findVars('discrete_smc_swarm_single')` (after defining placeholder values for `xi`, `xf`, `xf_ballistic`, `x0_step`, `simcase`) to audit the current dependency list.
